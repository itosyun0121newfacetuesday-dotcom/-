1. 分野の概要・全体像

資料：PDF 1〜2ページ

OSPFは、AS内で経路情報を交換するリンクステート方式のルーティングプロトコルです。各ルータがネットワークの接続状態を共有し、自分を起点とする最小コストの経路を計算します。エリア分割、経路集約、再配布を組み合わせ、大きなネットワークの経路制御と冗長化を実現します。

学習の軸：Helloで相手を知る → LSAを交換する → LSDBを同期する → SPFで経路を計算する → 障害時に更新する。

2. 本文内容の簡潔かつ分かりやすい解説

2.1 「ネットワークの地図」を共有して経路を計算する

観点OSPFの基本
分類・方式AS内で使うIGP。リンクステート方式を採用する。
下位プロトコルIP上で動作する。資料の通信例はIPv4。
交換する情報LSAでリンクやネットワークの状態を広告し、LSDBに蓄積する。
経路の計算ダイクストラの最短経路アルゴリズムで、自分を根とする最短経路ツリーを作る。
選択の基準資料の基本例では、同じ宛先・マスク長の経路をコストの合計で比較する。
規模への対応エリア単位で詳細情報を共有し、境界で要約・集約する。可変長サブネットマスクにも対応する。

同じエリアのルータは、そのエリアの接続状態を共通の情報として持ちます。ただし計算の起点はそれぞれ異なるため、LSDBを同期しても全ルータのルーティングテーブルが同じになるわけではありません。

通信先のアドレスを役割と結び付ける

宛先役割
224.0.0.5同一リンク上の全OSPFルータ。Helloや、DRからの更新通知などに使用する。
224.0.0.6同一リンク上のDRとBDR。DROTHERからのリンクステート情報の通知などに使用する。
相手のIPアドレス一部のやり取りではユニキャストも用いる。全パケットがマルチキャストとは限らない。
資料の主な説明対象は、イーサネットのようなブロードキャスト可能なマルチアクセスネットワークです。ネットワーク種別が変わると、DRの要否や通信方法も変わります。

2.2 コスト計算・ECMP・エリア

資料：PDF 1〜5ページ

コストは経路に沿って足し合わせる

リンクごとにコストを設定し、合計が最小の経路を選びます。資料では、明示設定がなければ帯域幅が大きいほど小さいコストになると説明しています。自動計算の具体式・基準帯域幅・装置の既定値は資料からは判断不可。

資料の例：拠点1 → 拠点3計算合計
a → b → e → f → i30＋100＋40＋10180
a → b → e → h → i30＋100＋30＋10170：選択
a → d → g → f → i40＋100＋30＋10180
a → d → g → h → i40＋100＋30＋10180

拠点2からは、c → d → g → f → iとc → d → g → h → iが、ともに40＋100＋30＋10＝180で最小になります。これらを同時に利用して分散するのがECMPです。

分散方法仕組み・注意点
フローモード送信元・宛先IPアドレス等の組合せを使い、フロー単位で経路を選ぶ。資料では通常用いる方法として紹介する。
パケットモードパケットごとに経路を選ぶ。到着順序が入れ替わり、不必要なTCP再送につながる可能性がある。
※資料外の補足：OSPFでは経路種別の優先関係もあります。同じ宛先プレフィックスなら、エリア内 → エリア間 → 外部Type 1 → 外部Type 2の順です。「どの経路でも、コストだけを比較する」とは覚えないようにします（RFC 2328 §11、§16）。

エリアは詳細な接続情報を共有する範囲

OSPFドメインを複数のエリアに分けると、各エリア内で詳細なリンク情報を共有し、エリア間では簡略化した経路情報を伝えます。資料の複数エリア構成では、エリア0をバックボーンとし、他のエリアを接続します。各サブネットは一つのエリアに属します。

ネットワークの区別意味
ポイントツーポイント2台のルータを結ぶ。資料はアドレスを割り当てる例とunnumberedを紹介する。
マルチアクセス複数台を収容できるネットワーク。ブロードキャスト型とNBMAに分かれる。
トランジット／スタブネットワーク資料では、マルチアクセス上のOSPFルータが2台以上／1台のみという区別で説明する。

2.3 DR・BDRと隣接関係、障害検知

資料：PDF 5〜8、15〜16ページ

DRはリンクステート情報の交換を効率化する

同一マルチアクセスネットワークで全ルータが互いに同期すると、組合せが増えます。そこでDR（代表ルータ）とBDR（バックアップ代表ルータ）を選び、その他のDROTHERはDR・BDRとの間でLSDBを同期します。DRはサブネットごとに選びます。

比較隣接関係の組合せ数
全組合せN×(N−1)÷2
DR・BDRを利用2×(N−2)＋1。資料の5台の例では10組から7組に減る。
  • DR・BDRはインタフェースのプライオリティが大きいものを優先して選ぶ。0は選出対象外。
  • 後から高いプライオリティのルータを追加しても、稼働中のDRは直ちに交代しない。
  • DR障害時はBDRがDRへ昇格し、新しいBDRを選ぶ。
※資料外の補足：選挙でプライオリティが同じ場合は、ルータIDの大きい方を優先します（RFC 2328 §9.4）。

ネイバーとアジャセンシーを区別する

関係何をしているか
ネイバーHelloを交換して、互いを認識している。
アジャセンシー（隣接関係）LSDBを同期する関係。ブロードキャストネットワークではDROTHER同士は通常、この関係を作らない。

初期同期では情報の差分を補い、同一エリアにLSAを行き渡らせます。構成変更時には、資料の基本例でDROTHERが224.0.0.6へ通知し、DRが224.0.0.5へ通知します。他のリンクにも伝わり、各ルータが経路を計算し直します。

Hello・更新・停止方法の違い

  • 資料のイーサネットの例はHello間隔10秒、Dead interval 40秒。BFDを使う高速な障害検知にも触れている。
  • 構成変化がなくても、資料では30分間隔のリンクステート情報更新を説明する。これはHelloとは別の処理。
  • 計画停止ではOSPFを明示的に停止すると、相手のタイムアウト待ちを避け、短時間の収束につながる。
※資料外の補足：30分は自己生成LSAを再生成するLSRefreshTimeです。一斉に全ルーティングテーブルを再送する周期ではありません（RFC 2328 付録B）。実際の障害検知・切替時間は設定に依存し、資料からは判断不可。

2.4 ABR・ASBR・LSAの役割

資料：PDF 8〜11、14〜15ページ

エリア内は詳細、エリア外へは経路の概要

ABRはエリア境界で、ネットワークアドレス・マスク・コストなどを別エリアへ伝えます。元エリアの内部構成を、そのまま隣のエリアへ広げるわけではありません。資料の例は「エリア2 → ABR → エリア0 → ABR → エリア1」の順に伝わります。

Type／名称生成元何を表すか・届く範囲
1 Router-LSA全OSPFルータ自身のリンクとコスト。生成元が属するエリア内。
2 Network-LSADRマルチアクセスネットワークと接続ルータ。同一エリア内。
3 Network-Summary-LSAABR他エリアの宛先ネットワーク・マスク・コスト。エリア境界で生成し、受信先エリア内へ広告。
4 ASBR-Summary-LSAABRASBRへの到達情報を他エリアへ伝える。スタブエリアには入れない。
5 AS-External-LSAASBROSPF外部から取り込んだ経路。通常のOSPFドメイン全体へ伝わるが、スタブエリアには入れない。
Type 3の「Summary」は、必ずしも複数プレフィックスを一つに集約したという意味ではありません。資料では、集約設定がなければ宛先サブネットごとに広告します。

パッシブインタフェースでも接続ネットワークは広告する

相手のOSPFルータがいない端末用ネットワークでは、Helloを送る必要がありません。パッシブ設定でそのリンク上のHello送信・隣接関係の形成を止めつつ、接続しているネットワークの情報は、他のOSPFルータへ広告します。

スタブネットワークとスタブエリアは別の概念

用語区別するポイント
スタブネットワーク資料ではOSPFルータが1台だけ接続するネットワーク。
スタブエリア外部経路のType 5やASBR情報のType 4を受け取らず、外向き通信にABRのデフォルトルートを利用する。
トータリースタブエリア上記に加え、通常のType 3のエリア間経路も抑え、Type 3のデフォルトルートを用いる。
※資料外の補足：スタブエリアは「ABRが1台だけ」という意味ではなく、複数のABRを持てます。外部LSAを扱わないという性質で区別します（RFC 2328 §3.6）。

2.5 再配布と経路のループ

資料：PDF 10〜14ページ

異なる経路制御の間をつなぐのが再配布

OSPFは、静的経路やBGPなど、OSPF以外で得た経路を取り込めます。これを再配布といい、実施するルータがASBRです。外部の経路をOSPFで扱える形式に変換し、OSPF用のコストを与えて広告します。変換時の値は慎重に設計します。

役割境界主な広告
ABROSPFのエリアとエリアType 3：他エリアの宛先、Type 4：ASBRへの到達情報
ASBROSPFと外部の経路制御Type 5：取り込んだ外部経路

再配布した情報が戻り、元の経路より優先されると危険

資料の例では、ネットワークXへのBGP経路が次の順に伝わります。戻ってきた経路が元の経路より優先される場合、データが循環します。情報が戻るだけで必ずループになるわけではなく、どの経路を選ぶかが重要です。

段階経路情報の伝わり方
1X → A：AはXへの元のBGP経路を学習する。
2A → B：Bが学習し、BGPからOSPFへ再配布する。
3B → C：CがOSPFで学習し、OSPFからBGPへ再配布する。
4C → A：Aに経路が戻る。これを優先すると、Aの次ホップがCになる。
経路情報の伝搬：X → A → B → C → A
誤選択後のデータ転送：A → C → B → A → …
IPv4パケットはTTLが0になるまで循環し得る。

資料が示す3つの対策

  • 再配布した経路を元のドメインへ再び戻さない。再配布の停止やルートフィルタリングで防ぐ。
  • 戻す必要がある場合は、元の経路を優先するように属性値を設計する。大規模構成では整合性の確認が難しい。
  • 可能であれば経路制御を統一し、再配布自体を不要にする。

デフォルトルートで外部経路を簡潔にする

内部ルータの外向き通信がASBRを必ず経由する構成なら、大量のインターネット経路を全て取り込まず、ASBRから0.0.0.0/0を広告する方法があります。資料の複数ISP接続例では、それぞれのASBRがデフォルトルートを広告します。

2.6 経路集約とNull経路によるループ防止

資料：PDF 9〜10、13〜15ページ

集約は広告数を減らすが、アドレスの範囲も広げる

ABRはエリア間経路を、ASBRは外部経路を集約できます。複数のプレフィックスをまとめるとLSAや経路表を簡潔にできますが、資料では明示的な集約設定が必要としています。Type 3を生成する処理と、複数経路を集約する設定を区別します。

資料の集約例含まれる範囲
実在する経路172.16.0.0/24、172.16.1.0/24、172.16.2.0/24
広告する集約経路172.16.0.0/22
余分に含まれる範囲172.16.3.0/24。この例では実在する個別経路がない。

デフォルトルートと集約経路が向き合うとループする

資料では、ABRのルータ0がエリア1の集約経路をFW側へ広告し、自身はFW向きのデフォルトルートを持っています。172.16.3.1宛てのパケットを受けると、個別経路がないため、対策なしでは次の動きになります。

ルータ0：個別経路がない → デフォルトルートでFWへ
FW：172.16.0.0/22に一致 → ルータ0へ
結果：ルータ0 ⇄ FW の間で循環する。

集約したルータに、集約範囲の破棄経路を置く

ルータ0の宛先次ホップ・処理目的
172.16.1.0/24 等実在するネットワーク側正常な通信を転送する。
172.16.0.0/22Nullインタフェースより具体的な経路がない集約範囲宛てを破棄する。
0.0.0.0/0FWその他の宛先を外部へ送る。

実在する/24経路は/22より長く一致するため、正常に転送されます。172.16.3.1には/24経路がなく、/22のNull経路が/0より優先されるため、FWへ戻さず破棄できます。これがロンゲストマッチと破棄経路を組み合わせる理由です。

複数のABRでは集約範囲をそろえる

同じエリアの経路を複数ABRから広告する場合、一方だけを集約すると、もう一方の長いプレフィックスが優先され、集約側の経路が選ばれなくなることがあります。資料では、複数ABRで集約方法を統一する必要を説明しています。

集約経路のコストは規格・設定による差があると資料に記載されています。対象機種の採用値やNull経路の自動生成の有無は、機種が指定されていないため資料からは判断不可。

3. 重要単語まとめ｜基本・経路計算

資料：PDF 1〜4、7、15〜16ページ

［OSPF／IGP］

要約：OSPFはAS内で使うリンクステート方式のIGP。

詳細：IP上でリンク情報を交換し、コストに基づいて経路を選ぶ。資料は主にイーサネットでの基本動作を扱う。

［リンクステート／LSA］

要約：リンクステートは接続状態、LSAはその情報を広告するための情報単位。

詳細：各ルータのリンクやネットワークの情報を伝える。ルーティングテーブルそのものを交換するわけではなく、受信側が計算に利用する。

［LSDB（リンクステートデータベース）］

要約：経路計算に必要なLSAを保持するデータベース。

詳細：同一エリア内で接続状態を共有する。各ルータは共通の情報から、自分を起点とする経路を求める。

［SPF／ダイクストラ法］

要約：自ルータからの最短経路ツリーを求める計算方法。

詳細：資料ではリンクのコストを用いて最小コスト経路を求め、ルーティングテーブルへ登録する。

［コスト］

要約：OSPFが経路の選択に使うリンクの重み。

詳細：経路に沿って加算し、比較条件が同じ経路では合計が小さい方を選ぶ。資料の既定の説明は、帯域幅が大きいほど小さい値になるというもの。

［ECMP（イコールコストマルチパス）］

要約：同じ最小コストの複数経路でトラフィックを分散する機能。

詳細：資料ではフロー単位とパケット単位の分散を対比する。後者は到着順序の逆転によって不必要なTCP再送を招く可能性がある。

［Hello／Dead interval／BFD］

要約：相手の確認に使うパケット、無応答を判定する時間、高速な障害検知の仕組み。

詳細：資料のイーサネットの例ではHello間隔10秒、Dead interval 40秒。BFDも紹介されるが、設定値や実際の切替時間は資料からは判断不可。

［フラッディング／LSAの更新］

要約：リンク情報を必要な範囲へ行き渡らせる処理。

詳細：構成変更時に更新情報を伝搬する。資料では変化がないときの30分間隔の更新も説明する。正確な意味は2.3の資料外補足を参照。

3. 重要単語まとめ｜隣接関係・エリア

資料：PDF 3〜9、14ページ

［ネイバー／アジャセンシー］

要約：Helloで認識した相手との関係と、LSDBを同期する隣接関係。

詳細：全ネイバーと必ず同期するわけではない。ブロードキャストネットワークのDROTHER同士は通常、アジャセンシーを形成しない。

［DR／BDR／DROTHER］

要約：リンク情報交換を仲介する代表、その予備、それ以外のルータ。

詳細：サブネットごとに選出する。DROTHERはDR・BDRと同期し、DR障害時にはBDRが昇格する。

［OSPFプライオリティ］

要約：DR・BDR選出の優先度を表すインタフェースの設定値。

詳細：大きい値を優先し、0は選出対象外。後から高い値のルータを追加しても既存DRを直ちに置き換えない。同値の比較は2.3の補足を参照。

［ポイントツーポイント／マルチアクセス／NBMA］

要約：2台間の接続、複数台を収容する接続、そのうちブロードキャスト非対応の接続。

詳細：資料は、イーサネットをブロードキャスト型、IPsec-VPNのようなトンネル構成をNBMAの例として扱う。動作はネットワーク種別で異なる。

［エリア／バックボーンエリア］

要約：OSPFドメインの分割単位と、複数エリアをつなぐ中心のエリア。

詳細：バックボーンの番号は0。資料の基本構成では非バックボーンエリアをエリア0へ接続し、ABRを介して経路情報を交換する。

［ABR（エリア境界ルータ）］

要約：OSPFの複数エリアを結び、エリア間経路を広告するルータ。

詳細：Type 3で宛先ネットワークを、Type 4でASBRへの到達情報を他エリアへ伝える。エリア内の詳細構成そのものは外部へ流さない。

［スタブネットワーク／パッシブインタフェース］

要約：末端のネットワークと、そのリンク上でHelloを送らない設定。

詳細：資料のスタブネットワークはOSPFルータが1台だけ接続するもの。パッシブにしても、その接続ネットワークの情報は他のOSPFルータへ広告する。

［スタブエリア／トータリースタブエリア］

要約：外部経路等を抑え、デフォルトルートを利用するエリア。

詳細：前者はType 4・5を受け取らず、後者は通常のType 3も抑える。デフォルトルートはType 3。ABR台数に関する注意は2.4の補足を参照。

3. 重要単語まとめ｜LSA・再配布・集約

資料：PDF 9〜15ページ

［Router-LSA／Network-LSA（Type 1・2）］

要約：エリア内のルータやネットワークの接続状態を表すLSA。

詳細：Type 1は各OSPFルータが生成し、Type 2はDRが生成する。いずれも同一エリア内で共有し、SPF計算の材料となる。

［Network-Summary-LSA（Type 3）］

要約：ABRが他エリアの宛先ネットワークを伝えるLSA。

詳細：ネットワークアドレス・マスク・コストを広告する。名称がSummaryでも、複数プレフィックスが集約されているとは限らない。

［ASBR-Summary-LSA／AS-External-LSA（Type 4・5）］

要約：ASBRへの到達情報と、OSPF外部の宛先経路を表すLSA。

詳細：Type 4はABR、Type 5はASBRが生成する。「外部の宛先」と「外部経路を広告したルータへの到達方法」を区別する。スタブエリアには入れない。

［ASBR／再配布］

要約：外部経路をOSPFへ取り込むルータと、その取り込み処理。

詳細：BGPや静的経路などの情報をOSPFの形式に変換して広告する。元の方式とOSPFでは指標が異なるため、コストなどの値を設計する。

［ルートフィルタリング］

要約：広告・受信する経路情報を条件により選別する処理。

詳細：資料では、再配布した経路を元のドメインへ戻さないための対策として用いる。データパケットの遮断と、経路情報の制限を混同しない。

［経路集約］

要約：複数プレフィックスを広い一つのプレフィックスにまとめる処理。

詳細：ABRやASBRが行い、広告数や経路表を減らす。集約範囲に実在しない宛先が含まれ得るため、破棄経路と合わせて考える。

［デフォルトルート／ロンゲストマッチ］

要約：特定経路がないときに使う0.0.0.0/0と、最も長く一致する経路を選ぶ規則。

詳細：資料ではABR・ASBRからデフォルトルートを広告する。集約経路より長い個別経路があれば、個別経路が優先される。

［Nullインタフェース／破棄経路］

要約：一致するパケットを転送せず破棄するための経路。

詳細：集約を行ったルータに集約範囲のNull経路を置くと、個別経路のない宛先がデフォルトルートへ戻って循環することを防げる。
